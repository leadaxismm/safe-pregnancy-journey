# رحلة الحمل الآمن | Safe Pregnancy Journey

منصة تثقيف صحي تفاعلية للحوامل خلال فترات الانتظار — تجمع حفر الباطن الصحي · مستشفى الولادة والأطفال.

> **تنبيه:** المنصة أداة تثقيف وتوجيه صحي، وليست نظام فرز طبي، ولا تشخّص الحالات ولا تستبعد الحاجة إلى الطوارئ.
> **المحتوى بحالة مسودة.** راجع `docs/CLINICAL_REVIEW.md` قبل أي استخدام مع المريضات.

## التقنيات
React 18 · TypeScript · Vite · Tailwind CSS · PWA (يعمل دون اتصال بعد أول زيارة) · Supabase (اختياري للإحصائيات ولوحة الإدارة) · Vitest.

> اخترنا React + Vite (بدل Next.js) لأن المنصة تُنشر كملفات ثابتة على أي استضافة، وتُحمَّل بسرعة على الجوال عبر QR، ولا تحتاج خادمًا للمريضات.

مزايا عامة: RTL كامل، خط Cairo مضمّن، وضع فاتح/داكن، الاستماع للنص بالعربية (Web Speech API على الجهاز)، أزرار ≥ 48px، دعم قارئات الشاشة ولوحة المفاتيح، احترام «تقليل الحركة».

### وضع الشاشات العامة
أضف `?kiosk=1` إلى الرابط (مثل `https://site/?kiosk=1#/`). بعد دقيقتين دون استخدام تعود الشاشة للرئيسية وتُمسح كل الإجابات.

### رموز QR
لوحة الإدارة ← رموز QR: اختر موقع الملصق، فيُنشأ رابط مثل `?src=er-waiting` ومُلصق قابل للطباعة. الوسم مجهول ويُظهر في اللوحة أي المواقع أكثر استخدامًا.

## الخصوصية
- لا تسجيل دخول للمريضات، ولا أسماء ولا هويات ولا ملفات طبية ولا معرّفات جلسة.
- إجابات الاستبيان والأعراض تبقى في ذاكرة الصفحة فقط ولا تُرسل أبدًا.
- يُرسل فقط عبر دالة `log_event` المتحقِّقة: زيارة، مشاهدة صفحة، «أُكمل الاستبيان» (دون الإجابات)، بدء/إكمال التعلّم، درجة الاختبار (0–5)، تقييم الرضا (1–5)، موسومة ببيئة البناء.
- حذف تلقائي للأحداث بعد 400 يوم.
- قبل أي توسّع لجمع بيانات صحية: تقييم أثر الخصوصية، موافقة صريحة، صلاحيات — وفق نظام حماية البيانات الشخصية (PDPL) وضوابط الهيئة الوطنية للأمن السيبراني.

## التشغيل
```bash
npm install
npm run dev        # تطوير
npm test           # 60 اختبار وحدة (محرك التصنيف + الحوكمة)
npm run check:content  # بوابة حوكمة المحتوى الطبي
npm run build      # بناء نسخة النشر في dist/
```
دون إعداد Supabase تعمل المنصة كاملة، وتعرض لوحة الإدارة **بيانات تجريبية** مع شريط واضح.

## Supabase
مشروع المعاينة الحالي: `safe-pregnancy-journey-preview` (eu-central-1). الترحيلات في `supabase/migrations/` (طُبّقت بالترتيب)، واختبارات الصلاحيات في `supabase/tests/rls_checks.sql`.

إضافة موظف: لأن التسجيل الذاتي ممنوع، يُنشأ الحساب بواسطة مسؤول (SQL Editor أو Dashboard ← Authentication ← Add user، مع تعطيل الـ trigger مؤقتًا إن لزم)، ثم:
`insert into public.admins (user_id, role) values ('<uuid>', 'editor');` (`viewer` للاطلاع فقط).

للإنتاج: مشروع Supabase **منفصل**، و`VITE_APP_ENV=production`، وتفعيل حماية كلمات المرور المسرّبة وMFA من لوحة Supabase.

## النشر
- **معاينة:** Netlify مشروع `spj-review-preview` مربوط بفرع `dev/review-fixes`. `netlify.toml` يضبط البناء والترويسات، و`netlify/edge-functions/review-gate.ts` يحمي الموقع بكلمة مرور (المتغيران `REVIEW_USER` و`REVIEW_PASSWORD` في إعدادات Netlify).
- **إنتاج:** يُرفض البناء آليًا ما لم يُعتمد المحتوى. مجلد `dist/` ملفات ثابتة تعمل على أي استضافة.

## حوكمة المحتوى
- كل المحتوى الطبي في `src/content/` فقط (لا نصوص طبية داخل الواجهات).
- أي تعديل طبي: رفع رقم `version` في `meta.ts` ← مراجعة الفريق الطبي ← تسجيل القرار في لوحة الإدارة ← تحديث `status` و`lastClinicalReview` ← النشر.
- ما دامت الحالة ليست `approved` يظهر شريط «نسخة مسودة» في كل الصفحات.

## قياس الأثر على الطوارئ
اللوحة تعرض المؤشرات الستة. بيانات الطوارئ تُدخل يدويًا من التقارير المعتمدة (أرقام مجمّعة). لا يمكن نسب أي انخفاض للمنصة دون تحليل مقارن قبل/بعد مع مراعاة العوامل الأخرى.
